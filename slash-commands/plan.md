# /plan — Propose a plan before coding

Create a short implementation plan. **Do not write code yet** unless the user asks to proceed.

## Steps

1. Restate the goal in one sentence.
2. List files or areas to inspect (with paths if known).
3. Break work into 3–7 small steps, each independently verifiable.
4. Note risks, unknowns, and questions for the user.
5. Define "done" (tests, manual checks, docs).

## Output format

```markdown
## Goal
...

## Steps
1. ...
2. ...

## Risks / questions
- ...

## Definition of done
- [ ] ...
```

Keep the plan small enough for one PR or one session.
