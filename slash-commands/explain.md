# /explain — Teaching mode

Explain code, errors, or concepts for a **beginner** Sudoku audience.

## Style

- Plain language first; jargon only with a short definition.
- Use analogies sparingly and accurately.
- Short sections with headings.
- One small example when it helps.

## Steps

1. Answer the user's question directly.
2. Connect to the file or error they care about.
3. Give one "try this next" action (command, file to open, or experiment).

Do not modify files unless the user asks.
