# Effective prompting

## Structure

Use four lines at the start of every task:

- **Goal** — one sentence
- **Constraints** — stack, policies, time
- **Scope** — files or areas allowed
- **Done when** — tests or checks that must pass

## Do

- One task per message when learning
- Paste errors verbatim
- Say "plan only" when you are not ready for code

## Avoid

- "Make it better" without criteria
- Huge pasted files; point to paths instead
- Asking for commits unless you mean it

See [`docs/best-practices/workflow.md`](../best-practices/workflow.md).
